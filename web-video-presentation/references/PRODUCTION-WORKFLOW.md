# 制作运行顺序

工作流和确认门见 [SKILL](../SKILL.md)；本页是执行时的短清单，不重复要求加载全部参考。

1. 读取用户材料与既有状态，确定 profile/outputMode 和缺项。依赖检查用 `bash <skill>/scripts/check-dependencies.sh --json`。
2. 一次完成口播或视觉节拍、outline、shot manifest、用户分镜。确认已经给出的参数直接记录，不另问。
3. 用户确认设计后脚手架；`--skip-install` 可先审查生成物，再在授权范围内安装官方依赖。立刻 `typecheck` 与 `build`，失败不报“可用”。
4. 做首章/代表镜头实际渲染，提交用户锚点验收。后续依约逐章、批量或并行；并行 agent 不能自批用户验收。
5. 音频仅在需要时执行。已确认 voice 复用；文案/声音改了才重合成相关片段。无声用 explicit step timing。
6. 重建 timing；字幕启用才导出/检查与预览。实拍运行 composition/assets 检查，透明运行 alpha smoke。
7. 先低成本 golden/连续帧/草稿定位问题，再全质量 final。draft acknowledge 只放开审批门，不放开类型/素材/合成技术错误。
8. 按 [QUALITY-GATE](QUALITY-GATE.md) 看实际产物和记录；最终用户批准后生成正式目标，按输出清单打包。

## 不同失败分开处理

- 编译失败：先修代码，不靠换渲染参数。
- 缺事实/素材：明确占位，不把假 UI/假数据当真实演示。
- TTS 不通：保留既有偏好，向用户确认备选，不能自动消耗另一云服务。
- 浏览器不可用：提供明确路径或获得安装授权；不用未知进程清理/静默下载绕过。
- 视觉不成立：回到对象/状态/镜头关系，不只加 glow/粒子/更大字体。
- 用户要求只做封面/透明素材：完成该范围，不强打完整视频项目包。
