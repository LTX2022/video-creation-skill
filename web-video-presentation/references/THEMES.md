# 预制风格系统：外观、构图与运动一起验收

保留原有 56 个主题 ID 和题材用途，但不再把 56 组颜色配置称为 56 套已验证成片风格。每套的当前状态以自己的 `theme.json` 和实际检验记录为准；`source-updated-render-review-pending` 不是可交付认证。

## 三层职责

1. `themes/<id>/tokens.css`：表面、文字、字体回退、线条、材质与视觉密度。
2. `themes/<id>/theme.json`：用途、设计意图、字体/对比度风险和检验状态。关键词命中不代表审美评分。
3. `templates/src/video/presets/`：实际对象、构图、三段动作和不同画幅的重排。默认示例应选择相应 preset，而不是给所有主题同一个硬编码纸色场景。

颜色差异不能代替结构差异。`variant` 必须对真实构图或对象操作有影响，不能只是一个不同的名字。同一家族可以共享可靠代码，但不得因此声称每套都已独立视觉验收。

主题与输出规格解耦：换主题不悄改 width/height/fps。横竖屏需要实际重排；Alpha 仅移除明确的场景底，保留主体表面、文字和必要阴影，再验证真实透明像素。

## 推荐时固定两栏

推荐入口不合并来源：`系统内置风格` 来自安装包 `themes/`；`用户自建风格` 来自用户显式授权的个人目录。即便用户风格以某内置主题为 baseTheme，也仍属于用户栏。缺个人库位置时不扫描、不假定为空。

```bash
SKILL='/absolute/path/to/web-video-presentation'
node "$SKILL/scripts/style-recommendations.mjs" --query="产品 流程" --limit=3
# 只有已获准读取这个目录才加此参数
node "$SKILL/scripts/style-recommendations.mjs" --query="产品 流程" --limit=3 --library-root=/approved/my-styles
# 用户要求展开时：完整输出全部版本，无分页、不截断
node "$SKILL/scripts/style-recommendations.mjs" --all --library-root=/approved/my-styles
```

输出 `sections` 固定有两栏，`source` 为 `builtin` / `user`；查询 `--limit` 各栏独立。用户栏 `state` 区分 `not-configured`（未读取）、`missing`、`inaccessible`、`invalid`、`empty`、`no-match`、`available`，不可把失败读库说成空库。失败时仍可展示内置建议，但必须展示用户栏错误并解决路径/权限后再查询；脚本不会自动申请或扩大权限。

个人项包含 `name/id/bestFor/version/status/package`，用途缺失就标未填写；完整展开以 ID 区分重名，展示每个版本，不只最新版。`matchedTerms` / `matchedEvidence` 是元数据词项命中，不是审美分数。用户项只匹配自身名称、用途、标签、描述和设计规则，不继承 baseTheme 用途，也不将参考 URL/权利声明当适用依据。旧包不需补字段即可列出；记录的 render-reviewed 不等于本轮独立验收。目录读取会验证完整本地包但不执行其代码，不访问引用 URL；授权目录中的文件也应受操作系统权限约束。

## 最小读取

未选主题先查摘要，选定后只读该主题；全库盘点才使用 `--all`。

从任意工作目录调用均使用已确认的 Skill 安装绝对路径；`SKILL` 不是客户项目路径。下面路径仅为占位，不是默认目的地。

```bash
SKILL='/absolute/path/to/web-video-presentation'
node "$SKILL/scripts/theme-summary.mjs" --query="科普 技术原理" --limit=3
node "$SKILL/scripts/theme-summary.mjs" --id=science-diagram
node "$SKILL/scripts/theme-summary.mjs" --all
```

脚本只做元数据关键词筛选，不返回画质评分，也不读取所有主题作为每章的模型上下文。

## 公共样式加载顺序

默认值 → 主题值 → 渲染态覆盖。当前约定为 fonts、base、tokens、animations、render。`base.css` 不得在主题后重新覆盖同名个性 token；渲染态舞台定位和无外框规则最后生效。数值级级联测试不等于浏览器样式计算或视觉通过。

## 角色化颜色契约

| Token | 用途与限制 |
|---|---|
| `--shell` | 舞台外背景；不决定视频尺寸 |
| `--surface` / `--surface-2` / `--surface-3` | 主背景、主体表面、内部层级 |
| `--text` / `--text-2` | 必需标题、正文与次级正文 |
| `--text-mute` | 必读的小标签；在所用平面底色上检查至少 4.5:1 |
| `--text-faint` | 非核心注脚或大字号弱提示，不能用来承载必读的小字；本轮平面源色目标至少 3:1 |
| `--text-disabled` | 非活动/装饰，不承载必要信息 |
| `--accent` | 品牌色、填色、线条与大图形；不假定可直接作为小字 |
| `--accent-strong` | 表面层上的必读强调文字，独立检查文字对比度 |
| `--accent-on` | 纯 accent 填色上的文字；不直接用于渐变、图片或透明底 |
| `--accent-soft` / `--accent-glow` | 从属叠层与局部辉光，不以全画面泛光代替材质 |
| `--rule` | 分隔、网格与装饰线，不套用正文对比度门槛 |
| status / chart 色 | 必须同时有标签、形状或线型，颜色不证明数据真实 |

这些是源色与角色检查，不是完整可访问性认证。透明叠加、复杂背景、实际字体大小/字重、编码与目标显示设备仍需看画面。不要为了让每个装饰 token 达到 4.5:1 而把所有层级拉成同样亮。

## 字体与个性参数

- `--font-display-cn/en`、`--font-body`、`--font-mono` 指定期望的字体类别与离线回退。
- 包内不包含字体二进制；写了字体名不等于机器上已安装。中文缺字、真实字重、替代字体换行必须检查，不静默下载或假称跨机器像素一致。
- 默认不用远程字体；仅在明确授权后使用 `fonts.remote.css` 或指定安装来源/位置。
- `.card` 消费 `--card-border-w`，`.display-en` 消费 `--font-display-weight`，body 消费 `--body-leading`，`.label-mono` 消费 `--label-tracking`；都有保留旧行为的回退。
- `--r-card`、`--hero-num-*`、`--rule-w/style`、`--stage-pad-*`、阴影/纹理体现主题性格。不是每类文本都继承同一个字重，也不把所有元素都做成卡片。
- `--surface-pattern-blend` 必须有真实消费者。纹理/暗角默认从属，不能压低正文或抢过运动主体。

字体、字阶、留白和材质的变化都可能改变布局，所以切换主题后出现问题不一定是章节错误，也可能是主题、字体、级联、构图或内容适配问题。

## 构图和动态

实际 runtime preset 以确定性 `frame / fps` 和同一章时间轴驱动。`mood` 只是情绪描述，不是动画实现；CSS duration token 也不自动驱动逐帧渲染。

每套保留的 preset 应做到：

1. 主对象可辨认；不是全部画面都由标题、段落和卡片占据。
2. 对象变化有内容意义，至少区分建立、操作/变化、结果停留；转场不是遮盖静态页面的借口。
3. 构图、字阶、密度、主图结构、动作时序里有真实选择，不只是改 accent。
4. 横竖屏、长中文、字幕、安全区和透明输出各有适用测试，不强行把不适合的布局拉伸。
5. 同一主题可以在经过设计的明暗场、远近景之间切换，但保持清楚的视觉语言；不把“不许明暗切换”当通用规则。

原 flow-continuity 示例仍可用于流程解释，不再作为所有风格的唯一默认构图。既有章节可继续自定义内容，但必须消费语义颜色，不能写死纸色/深墨而宣称支持任意暗色主题。

## 初始化与切换

新项目必须使用客户指定的独立空目录。初始化前按 WORKSPACE-SETUP 检查工具和授权；不能为了预览把输出写进 skill 根目录或用户桌面。

切换完整预制风格需要同步：所选 tokens、项目主题 ID、runtime preset 选择及相关设计记录。仅复制 `tokens.css` 只切外观，不等于切换完整场景。不要通过重跑脚手架覆盖已有项目。

变更后重新审查受影响的标题、图形、字幕、明暗关系和导出；旧主题的截图、封面与验收记录不能自动成为新主题的证据。

## 每套的验收证据

- 源级：ID/元数据完整、变量可解析、角色对比度、导入顺序、无意外远程依赖。
- 图像级：真实组件的开场/动作/结果帧、长中文和横竖屏。SSR/SVG 的离线栅格化必须标明引擎，不冒充浏览器渲染。
- 动态级：完整动作片段与实际最终编码，检查对象连续、速度、停留、闪烁和遮挡。文件哈希、字节差和关键词不能给出审美或运动语法通过结论。
- 工程级：在授权的干净项目里完成真正的 Remotion 渲染、修改重出与打包。插件/字体/目标剪辑软件的兼容性另外核验。
- 用户级：实际用户反馈和确认。自审或技术测试不填成用户接受。

有一套没有跑完，就给那一套保留明确状态，不用一个全局“56/56 已通过”掩盖缺口。交付只承诺已验证的环境、用途与边界。

## 反模式

- 30 个主题共用同一结构参数后只换名称/颜色。
- 新增状态字段、形容词或“高级/企业级”文案，但没有对应场景实现。
- 所有主题都改成黑底金色粒子，或每个镜头都套同一种卡片。
- 把稀疏抽帧/源色对比度/一次脚本退出 0 当成完整视觉通过。
- 未检查字体就把替代字体当原设计；未经授权下载、全局安装或写到客户工程外。
- 为统一一条死规则而删掉适合该题材的品牌色、明暗变化或必要标注。
