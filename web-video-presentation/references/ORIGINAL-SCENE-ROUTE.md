# 无素材原创：单画面 / 单镜头

用户不提供素材也可以只做一个画面；不强制片头、字幕、旁白、章节、标题或转场。这里的交付是**画面本身**，不是拿抽象背景替代已有信息型视频的内容。先确认目标是静态图还是动态镜头；“纯生成”不能擅自等同于云端生成式 AI。

## 先选路线，不替用户同意上传或费用

| 路线 | 适合 | 边界与授权 |
|---|---|---|
| 本地程序化原创（本实现） | 抽象光雕、能量花冠、星环、可精确复现的运动 | 无第三方素材、无上传、无模型调用，无新增服务费；仍消耗本机计算资源。用户同意本地生成后填 `localProcessingAuthorized: true`。 |
| 图像模型 → 静态图 | 语义丰富的原创场景、人物、写实/绘画构图 | 本脚本未接入；先检查真实可用工具、费用、隐私/保留规则、输出权利；获得所需授权后另走该工具流程。先做候选图再验收，不声称任意提示词都好看。 |
| 图像模型 → 本地运动 | 已验收图片的推拉、视差等 | 需用户认可先生成静帧再动；单张图不能宣称真实 3D、关节动作、遮挡重建。 |
| 图像/视频模型 → 动态镜头 | 复杂物理、人物/生物动作与写实场景 | 未实现、未验证；仅在工具实际可用且用户明确同意服务/上传/成本后用。逐帧检查主体漂移、肢体、闪烁、无缝连接；不可把“有模型工具”写成“已成功产片”。 |

程序化不满足题材时必须说明，不把所有请求都收敛成发光圆环。这里是两个原创视觉机制的起点，不是“所有风格已覆盖”的固定万能模板。用户说不够炫酷，应重新设计主体、光线、形态、空间/镜头，而不是只增加 bloom 或粒子。

## 发散构思与后端选择（不是配方菜单的边界）

先写一句「主体是什么、最迷人的变化是什么、观众要感到什么」，再选表现方法。没有素材不是没有主体：可以是微观生态、液态金属、漂浮建筑、折纸生物、宇宙风暴、珐琅机械、织物生长、彩色玻璃、光学错觉、手绘抽象、极简雕塑，或用户的全新想法。不能把以上列举当穷尽列表，也不能把明亮/炫酷仅解释为霓虹暗底。

至少提出两个在**主体或材质或空间机制**上不同的方向，而非给同一个圆环换颜色。例如：①明亮天空中的玻璃漂浮城市，镜头穿越结构；②黑场中的有机光雕缓慢呼吸；③白底黏土生物夸张舒展。明确本包仅直接实现②中的一种光丝配方，其余需真正创作并测试对应场景，不可只改名称就宣称支持。

按需求选最少且足够的后端：

- **代码 / Canvas / SVG / Remotion**：精确几何、图形、交互逻辑、版式或确定性运动；使用项目已允许的渲染器。需要浏览器而浏览器被拒时报告阻塞，不换命令绕过。
- **本地 CPU 栅格（当前示例）**：可离线的程序化抽象画面，不擅长复杂语义写实；允许另写全新视觉机制，不能把参数范围当创作上限。
- **3D / Blender / Three.js**：需要材质、实体体积、镜头穿越、准确遮挡或灯光反射时更合适；先验证实际安装、运行权限与渲染资源，不默认可用。本次没有执行/验证 3D 渲染。
- **图像模型**：先锁定有语义和审美的单画面；仍需用户选择并复核结果。调用需要现有工具与相应授权，不自动购买额度。
- **视频模型**：需复杂生成运动时考虑；从已验收图/明确描述起步，说明可控性和时序一致性风险。
- **混合**：模型静帧 + 原创代码光效、3D 主体 + 2D 合成等；逐层记录来源与权限，不因“混合”隐藏上传/付费行为。

本参考给出选择协议，不表示上述所有后端已有适配器。本地样片的运行成功不等于自由文本到任意视频已实现。设计验收应允许用户否决配方并选择全新方向。

## 可直接运行的独立 CPU 后端

要求 Python 3.10+、NumPy、Pillow；动态输出额外需要 FFmpeg（libx264）及 ffprobe。依赖缺失则报告；不要默认联网安装。这是独立可选的本地生成路径，不是 Remotion/Chromium 渲染，也不是绕过浏览器拒绝的替代执行方式。不重试被拒操作。现有主视频 scaffold 保持原样。

从任意当前目录执行（把 `SKILL_ROOT` 替换为实际安装目录的**绝对路径**，不要依赖调用方 cwd）：

```sh
SKILL_ROOT="/absolute/path/to/web-video-presentation"
OUT_ROOT="/absolute/path/to/new-render-parent"
# 4 秒 / 24 fps / 960×540 的原创动态镜头
python "$SKILL_ROOT/scripts/original-scene.py" "$SKILL_ROOT/examples/original-scene/corolla-shot.json" --output "$OUT_ROOT/original-corolla"
# 1280×720 原创静态图，不产空视频
python "$SKILL_ROOT/scripts/original-scene.py" "$SKILL_ROOT/examples/original-scene/orbital-still.json" --output "$OUT_ROOT/original-orbital"
python "$SKILL_ROOT/scripts/test-original-scene.py"
```

输出目录必须不存在；输出自身及任何祖先含符号链接（包括悬空链接）均拒绝，不会覆盖旧交付。输出应放在用户授权的工作区内；此检查不替代操作系统沙箱，也不承诺抵御恶意并发替换路径。脚本产生 `contract.json`、关键帧 PNG、`evidence.json`，动态另产无音频 H.264 `scene.mp4` 及 encoder 日志。此路线不承诺透明背景、模型调用、资产导入、真实 3D 或音频。失败留下的目录是诊断材料，不是成功交付；修复后用新目录。

### 视觉机制与可改参数

- `corolla`：30 束带深度投影的扭曲光丝交织成不规则花冠；冷暖分区、低频空气光、运动高光和疏密变化的星尘。
- `orbital`：不同倾角/半径的椭圆轨道，暖色高光；不是仅替换花冠颜色。
- `palette`：prism / solar / aurora；`composition`：center / left / right（后两者留白）。
- `seed`：星尘与远景位置；`time`：静态采样的时间；`motion`：运动速度，0 冻结，非循环保证。
- `exposure`：0.3–2，柔性亮部压缩；不把全屏高亮或白色过曝当作灿烂。
- 偶数宽高 128–1920，fps 1–60，frames 1–1800，且宽×高×帧数最多 1.2 亿（先检查再渲染）。动态渲染/编码期限 180 秒，版本查询 5 秒、最终探测 30 秒；超时/启动失败不产生成功 evidence。`still` 必须 1 帧；`shot` 至少 2 帧。时刻由全局帧解析计算，不依赖墙钟、逐帧随机数或上一帧状态。
- 源码几何完全原创，没有复制外部 shader/资产。程序化结果不是“AI 视频模型生成”。同一合同和依赖版本保证源像素复现；不同编码器版本的 MP4 字节不保证相同。

## 先锁关键帧，再验动态

1. 若用户没有具体审美偏好，用明确标注的方向出两张真正不同的候选（如棱镜花冠 vs 太阳星环）。先静态预览；确认主体比例、层次、留白、亮暗对比。不要承诺主观“必然炫酷”。
2. 静帧需要主体/中景/远景层次与有节制的高光；本例的亮部覆盖率只是检测指标，不是审美分数。
3. 动态检查开头/中段/末尾，最好解码最终 MP4 形成接触表，确认不是黑帧、冻结画面或截图冒充视频。脚本自动核对实际 codec/帧数/分辨率/fps/时长，全部吻合才写成功证据；播看是否平滑，避免闪烁。静帧源证据不能替代编码视频的像素检查。
4. 保存合同、种子、依赖版本、关键帧及视频 SHA-256；自动测试通过仅代表工程性质，不代表审美已验收、浏览器成功或视频模型通过。
5. 接入现有项目时把批准后的 PNG/MP4 作为真实本地资产使用并保留来源合同；不能因本路线成功，就将主 Remotion 渲染标为成功。

## 设计借鉴（只借方法，未使用第三方媒体/代码）

- [Remotion：frame → visual](https://www.remotion.dev/docs/idea)：任意帧可重现；本实现用解析帧时钟。
- [Motion Canvas time events](https://motioncanvas.io/docs/time-events/)：复杂定制镜头可把 anticipation / hero / settle 与时间解耦。本例是持续运动光雕，不虚报实现叙事阶段状态机。
- [ViMax](https://github.com/HKUDS/ViMax)：先构图候选与检查点，再生成动态；该项目/其模型服务并未被本 Skill 安装或调用。

## 运行时与依赖许可

Skill 包只包含原创源码/合同，不包含 NumPy、Pillow、FFmpeg 或 libx264 二进制；它们不因使用本仓库而改用本仓库许可。运行时版本保存在 evidence（Python/NumPy/Pillow，以及动态模式的 FFmpeg/ffprobe）。本次环境包元数据：NumPy 为 BSD 风格条款且其发行包包含各自许可的组件，Pillow 为 MIT-CMU；应查看实际安装包的完整许可证。FFmpeg 许可取决于构建选项，本环境 `ffmpeg -L` 明确为 GPL v2 或更新版本，使用了 libx264。分发/重打包编码器或其依赖前必须检查相应发行版及 libx264 的完整许可证，不能以原创输出为由移除运行时版权通知。该路线没有把 FFmpeg/libx264 二进制重新分发给用户。
