# Visual Models

画面模型先于动画。先问“什么操作能使关系可见”，再从内容选表示，不从模板选样式。适合检验的命题保留基线或只变一个条件的反例；动画展示的是模型结论，不替代事实证据。

## 模型速查

| 内容关系 | 优先画面模型 |
|---|---|
| 增长 / 下降 | 折线、柱形、波形、计数器、面积扩张 |
| 密度 / 热度 | 热力图、网格、地图、色块矩阵 |
| 因果 | 因果链、故障树、箭头路径 |
| 流程 | pipeline、状态机、泳道、步骤轨道 |
| 对比 | 分屏、矩阵、before/after、差异高亮 |
| 层级 | 树、堆叠层、剖面、嵌套容器 |
| 关系 | 节点图、网络图、依赖图 |
| 时间 | 时间线、版本演进、阶段条 |
| 空间 | 地图、3D/伪 3D、深度层 |
| 产品 | 真实截图、界面状态、操作路径 |
| 代码 / 系统 | 终端、文件树、数据流、请求链路 |

## 使用要求

- 每章至少有一个核心视觉机制来自内容本身。
- 每个 step 至少有一个内容对应画面，不允许只有抽象背景。
- 每个 step 必须同时决定 `visualModel` 与 `compositionModel`：前者回答“内容是什么关系”，后者回答“画面如何成片”。`compositionModel` 见 [`STYLE-BENCHMARKS.md`](STYLE-BENCHMARKS.md)。
- 视觉语言先按行业 / 题材定调：企业汇报要信息清晰，SaaS / 产品演示要界面和状态可信，艺术与媒体题材可以更 editorial，教育内容要路径和层级清楚。参考成熟模板站的分类思路，但不要照抄版式。
- 可数据化内容优先数据可视化。
- 字幕开启时不靠复述整句口播解释；必要术语、单位、公式、代码及字幕仍保留，用对象的操作承担核心关系。**v2.2.16：每 step `onScreenText` 最多 2 条（开头 / 结尾点题步最多 3 条），超出由 `validate-screen-text` 拦截。**
- 没有真实数据时要标明 placeholder，不编数字。

## 3D / 伪 3D

只有当内容有空间、层级、系统结构、产品外形或路径关系时使用。3D 不是装饰；它必须解释内容。
