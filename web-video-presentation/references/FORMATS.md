# 画幅、帧率与安全区

## 规格

新项目默认：`landscape` 1920×1080（16:9），`portrait` 1080×1920（9:16）。旧 portrait 1440×3200 为 9:20，保持兼容但不得称标准 9:16；迁移先记录用户选择，重排构图并重做 QA，不只改宽高元数据。

项目 fps、帧数和时长要显式记录。**当前脚手架CLI只接受24–120的整数fps，默认60**；源素材可为分数帧率并显式resample。目标要求30000/1001等精确分数项目帧率时，现成CLI不支持，需明确扩展并验证，不能声称已原生支持。选择受目标平台、实拍和宿主编辑器影响；不要把 60fps 当所有项目唯一答案。旧模板默认 fps 可继续使用，但有底片时优先决定是否匹配其精确速率。29.97 与 30000/1001 不应混用来偷换精确时间，当前运行时若不支持某速率应说明限制。

源视频的尺寸/fps 不必原生等于输出。适配见 [VIDEO-ASSETS](VIDEO-ASSETS.md)：明确 crop/contain/cover、resample/reject；复帧/丢帧不是光流。实际内容可读、时长和同步才是验收对象。

## 重排而不是缩放

竖屏给主对象足够空间，流程按纵向或分镜分段；不要把一张横向全图缩成细小文字。多个数字要有共同单位/基线，避免重排后暗改比较意义。

安全区以目标平台 UI 和真实设备预览为依据，不把固定像素表当所有平台规则。字幕、平台按钮、人物脸/手、产品关键操作分别规划；局部 Alpha 前景还要记录锚点与非透明包围盒。

## 验收

最终编码宽高、fps、帧数与 manifest 一致；手机尺寸下读数可辨；安全区无冲突。比较参考视频可以学习布局，不据参考低分辨率静默降低成片质量；不要仅靠元数据宣称画质通过。

## 客户指定其它尺寸

脚手架没有任意宽高开关时，不要虚构 `--width` / `--height`。在客户已确认的独立项目内同步 `src/config/videoFormat.ts` 的 width/height、`project-state.json` 的 videoWidth/videoHeight，以及 `.web-video-presentation-project.json` 的 width/height。fps 也须保持一致；变更后重新生成 timing、typecheck、关键画面与需要重确认的输出证据。新尺寸会改变输入修订，旧渲染/确认不能冒充当前结果。具体960×540/180帧集成示例见 `examples/motion-customer-smoke`。
