# 流程元素：保留用户已喜欢的表达能力

这类动画的主角是可追踪的信息对象，不是背景图、逐句文字卡或机械外壳。它与机制解释并列：流程讲“对象去了哪里/状态如何变”，机制讲“什么规则使结果发生”。

## 已有 28 秒片段的实际观察

本次升级查看了用户喜欢的《资料归档助手》17 张关键帧接触表、storyboard 及 Python 绘制源，未在此参考中声称逐帧播放整片。规格为 1920×1080、30fps、28s；原片是 Python/Pillow 生成的概念流程演示，**不是 Remotion 工程，也不是真实产品操作/客户案例**。不将原视频或其二进制放入本 skill。

| 区间 | 实际对象/动作 | 解释作用 |
|---|---|---|
| 0–4.5s | 四条编号记录错时从不同方向滑入 | 建立输入与对象身份，后续有编号可追踪 |
| 4.5–10s | 聚焦记录01，字段标签逐项替换，日期高亮转换，保留原始值说明 | 把“标准化”落实为具体字段变化，而非只显示一个处理图标 |
| 10–15.5s | 两条同名记录高亮比对、括线连到“疑似重复”，缺失日期单独标出 | 判断有可见依据；“疑似/待核对”避免把演示判断冒充确定结论 |
| 15.5–22s | 编号记录沿不同曲线路径进入建议归档/错误两份清单 | 位移表达分类，编号保留身份，不重新生成无关联卡片 |
| 22–28s | 指针代表人工选择，勾选描绘后路径出现，再移动记录到归档示意 | 原因先于结果；用户确认是动作门，不是装饰勾号 |

可复用的是：统一对象身份、字段级变化、顺序揭示的证据、路径分流、确认后才执行，以及结果停留。米白/青绿、纸卡阴影和具体秒数只是该片选择，不是通用规则。

## 原创重制模式

`建立对象 → 聚焦一个变化 → 显示判据 → 按结果分流 → 条件满足才执行 → 留下可读结果`。

在 Remotion 中重新实现时，稳定 `objectId` 与结构化记录驱动文字/位置/状态；同一记录跨 narration steps 保留身份，不因 step 局部帧归零而重新入场。先写保留/移位/变状态/拆分/合并对应，再求形状插值；只因外形相同不可匹配。日期示例保持原始与标准化值；分流由同一规则结果决定；用户确认用导演事件，而不是组件渲染时触发真实操作。所有运动按 frame 求值，可独立输出前景 Alpha。

可运行的原创参考在模板[src/examples/flow-continuity](../templates/src/examples/flow-continuity/FlowContinuity.tsx)：同一objectId跨步移动与获批，状态/读数来自同一模型；它不是原片复刻或产品操作证据。适合数据清洗、审批、排队、搜索、资料处理、AI 输入输出等。**不用**：只有品牌情绪没有流程、没有证据却声称自动识别准确、或想靠满屏箭头掩盖步骤缺失。若存在真实机制，则按 [MECHANISM-DESIGN](MECHANISM-DESIGN.md) 补状态模型，不硬把记录卡改为机器零件。
