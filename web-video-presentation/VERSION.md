## 版本号递增规则（Version Bump Policy）

本 skill 采用语义化版本 `MAJOR.MINOR.PATCH`（如 `2.5.0`）。每次修改完成后，按修改幅度对版本号递增，并在 `VERSION.md` 顶部新增一条 Summary、在 `VERSION.json.notes` 追加发版说明。

| 修改幅度 | 递增位 | 示例 | 典型场景 |
|---|---|---|---|
| **小修（PATCH）** | 第三位 `PATCH` | `2.5.0 → 2.5.1` | 单个 bug 修复、文案勘误、单条规则补充、单文件小调整、不改变既有工作流 |
| **中修（MINOR）** | 第二位 `MINOR`，PATCH 归零 | `2.5.1 → 2.6.0` | 新增规则章节、新增 profile/主题、调整既有红线（如字幕字数/位置/封面规格）、工作流门禁增强、多文件协同改动 |
| **大修（MAJOR）** | 第一位 `MAJOR`，后两位归零 | `2.6.0 → 3.0.0` | 项目重构、工作流根本性变更（如 Vite→Remotion）、破坏性兼容改动、profile 体系重建 |

### 操作清单（每次发版必须完成）

1. 更新 `VERSION`（纯文本 semver）、`VERSION.json` 的 `version` / `publicVersion` / `internalRevision`、`VERSION.md` 顶部 Current version 行、`manifest.json` 的 `version` 字段——四处必须同源。
2. `VERSION.json.releaseDate` 改为当天日期。
3. `VERSION.md` 顶部新增 `## vX.Y.Z Summary` 章节，写明本次改了什么、改了哪些文件、对应哪条客户反馈。
4. `VERSION.json.notes` 数组追加一条 `Starting in vX.Y.Z, ...` 开头的发版说明。
5. 若涉及客户反馈事故，同步在 `C:\PUBLIC-EXAMPLE\修改记录\<日期>\` 沉淀修改证据。
6. **执行打包到交付目录**（v2.5.0 起强制）：运行 `node scripts/package-skill.ts`（或 `npx tsx scripts/package-skill.ts`），把 skill 本体复制到 `VERSION.json.deliveryDirectory`（`C:\PUBLIC-EXAMPLE\交付-web-video-presentation`）并生成 zip + `delivery-manifest.json`。**版本更新后未打包到交付目录 = 发版未完成**。打包完成后确认交付目录存在 `web-video-presentation/` 子目录、`web-video-presentation-v<版本>-delivery-<时间戳>.zip`、`delivery-manifest.json`，且三者版本号一致。
7. **追加交付目录的 VERSION-CHANGELOG.md**（v2.5.0 起强制）：交付目录根目录维护一份独立的 `VERSION-CHANGELOG.md`（不在 skill 主目录内，不被打包进 zip）。每次打包后必须在该文件追加：版本号、包名、核心更新、验证结果、SHA256；并更新顶部「当前最新主线版本」段落的版本号、包名、SHA256、核心变更摘要和「最后更新」日期。**打包后未追加 VERSION-CHANGELOG = 发版未完成**。

### 判断「小修 / 中修 / 大修」的边界

- 改一个错别字、补一行注释 → PATCH。
- 新增/收紧一条会影响所有后续项目的规则（如字幕字数从 15-20 改 10-15、封面分辨率改 1080×1440、新增抖音审核合规红线）→ MINOR。
- 把整套渲染管线、profile 体系或组件架构推翻重做 → MAJOR。

拿不准时按**上一档**处理（即影响更大那一档），避免低估改动影响导致下游项目引用错误版本号。

## How Agents Should Read The Version

This skill may be delivered without a `.git` directory. Do not use `git log`, `git describe`, file timestamps, or project folder names to infer the version.

Read one of these files from the skill root:

1. `VERSION` — plain semver, easiest for scripts.
2. `VERSION.json` — structured metadata for agents.
3. `manifest.json` — skill manifest, also contains the same `version`.

PowerShell:

```powershell
Get-Content .\VERSION
Get-Content .\VERSION.json | ConvertFrom-Json
```

Bash:

```bash
cat VERSION
node -e "console.log(require('./VERSION.json').version)"
```

Expected value:

```text
2.2
```
