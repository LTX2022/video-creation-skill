# 按需深度复盘报告

完整修改全记录使用全部适用章节；只问一个耗时/问题时使用精简答复，不强制产生整份报告。缺口必须保留。

## 工作流优化候选判定

本节用于把项目复盘转成三个视频工作流的改进输入。候选默认“未批准”，必须有证据、拟修改位置、预期收益及验证计划。候选不是执行授权，不自动修改代码、skill、系统、依赖、外部任务或开启后台监控；只有后续明确授权才进入独立实施/验证流程。

将每条用户反馈映射到一个或多个规则层：

- `content-planning`：script / outline / 信息池 / step 拆分。
- `visual-design`：构图、字体、画面密度、素材、反 AI 味。
- `cover-design`：封面标题、字号、主视觉、背景、overlay、参考图对齐、封面生成方式。
- `motion-timing`：节奏、句级字幕、自动推进、音频闸门。
- `asset-pipeline`：真实素材、OpenDesign、图片路径、静态资源。
- `tts-subtitle`：provider、voice、格式、字幕切分、时长。
- `render-validation`：preflight、doctor、golden、lint、inspect、smoke、hash。
- `agent-process`：Checkpoint Plan、第一章 anchor、逐章验收、用户终止。
- `tooling-bug`：脚本、端口、入口文件、文件格式、系统依赖。

建议修改位置要具体到被复盘 workflow 实际存在的文件类型；以下是目标项目示例，不是本 skill 包中应存在的本地链接，也不授权读取外部路径：

- `SKILL.md`：硬节点、总流程、门禁、用户交互。
- `references/CHAPTER-CRAFT.md`：视觉章节实现和自检。
- `references/QUALITY-GATE.md` / `HYPERFRAMES-QUALITY-GATE.md`：验收规则。
- `references/COVER-WORKFLOW.md`：封面标题、版式层级、主视觉、背景、参考图对齐规则。
- `references/TTS-ROUTING.md` / `AUDIO-SUBTITLE-SYNC.md`：音频字幕。
- `templates/scripts/*`：可自动化修复或验证的脚本；封面生成命令问题优先指向 `generate-cover.ts`，遮挡/像素证明问题优先指向 `validate-cover.ts`，打包漏封面优先指向 `package-delivery.ts`。
- `templates/*manifest*.json`：需要让项目保留的结构化证据。

### 封面问题归类

封面问题不要只写成普通 `visual-design`。按以下规则归类：

- 项目明确要求的 overlay 缺失/不可用，或未经同意绕过约定封面流程：归为 `cover-design` + `render-validation`。仅有确切绕过证据才记录 `cover workflow bypass`；获准 still 不自动违规。
- 用户说“字太小”“标题太小”“不吸睛”“不像参考封面”：归为 `cover-design` 核心缺陷。
- 用户提到 `新版测试封面.png` 或 `参考视频封面.png`：必须记录参考图路径，并描述差异是标题尺度、主视觉、背景、底部品牌区、overlay 还是整体层级。
- 主视觉未满足已批准目标（如与内容无关、层级不清）：归为 `cover-design`，可建议修改实际封面工作流或组件；单帧/通用图标本身不等于违规。
- 要求封面时，`cover:validate` 未执行、`cover-report.json` 缺失或封面未进交付包：归为 `render-validation`；不要求封面时标记不适用。

## 反馈证据完整性评分

每份文档必须评分，避免“看似完整但无法复盘”。

| 分数 | 含义 |
|---:|---|
| 5 | 证据完整，可用于讨论修改候选；不代表已获实施授权 |
| 4 | 少量缺口，但不影响根因判断 |
| 3 | 可复盘现象，根因需要推断 |
| 2 | 只有总结，缺少原话或文件证据 |
| 1 | 只有结果，没有过程 |
| 0 | 无证据 |

总分仅辅助描述证据覆盖，不能代替硬门禁或掩盖关键缺口；不适用的维度列 N/A 并调整分母，不伪造满分。全部五项适用且总分低于 18/25 时，或任意情况下存在关键证据缺失/矛盾（用户批准、目标最终产物、验证结果、反馈来源等），都在文档顶部写并列明缺口：

```markdown
> 证据风险：本记录缺少足够的原话 / 文件 / 验证证据，不建议直接作为 workflow 修改依据。
```

## 拒绝执行模板

仅用于缺少触发授权、项目仍在进行且未终止，或必要读取/写入权限未明确时。已授权完成/终止项目的证据缺失应写风险报告，不因门禁失败拒绝记录。

```text
Fix-Agent 暂不能执行。当前状态：
  - 用户触发：[✓/✗]
  - 项目类型：[adapter / 未识别]
  - 最终输出：[✓ 正式 / △ 部分/草稿 / ✗ 未找到]
  - 用户验收：[✓ 全部 / △ 部分 / ✗ 未找到]
  - 验证门禁：[✓ 通过 / △ 部分 / ✗ 未通过]

缺少：[列出缺失项]
若项目已终止，可用自然语言明确要求按未完成状态复盘。已有明确终止与复盘请求时不要重复索要精确口令；证据缺口会如实保留。
```

## 自检清单

写入文件前逐项确认：

- [ ] 文档标明 adapter、被复盘skill版本、Fix-Agent版本、outputMode/schema及实际项目/验收状态。
- [ ] 用户原话逐条记录并注明来源；摘要转述未伪装为精确原话，敏感内容已脱敏。
- [ ] Remotion/OpenDesign/HyperFrames 没有混用错误字段。
- [ ] HyperFrames 项目没有被要求存在 `presentation/`、`narrations.ts` 或 Remotion 输出。
- [ ] 未完成 / draft 项目明确写出风险。
- [ ] 封面问题已单独进入 `封面设计记录`；未把“字太小 / 不像参考 / 抽帧替代 cover:generate”埋在普通视觉问题里。
- [ ] 封面适用性与 bypass 有该项目约定及行为证据，未把 still 本身判违规。
- [ ] `工作流优化候选` 有证据/验证计划，默认未批准，未当作已实施修改或自动执行授权。
- [ ] 证据评分诚实，关键缺口独立告警，不用总分掩盖门禁失败。
- [ ] 无测量写unknown；估计有依据/范围；失败/重试/中断保留；并行sum不当wall-clock，不重复计成本。
- [ ] 全量核对outputs[]及适用视频、manifest、验证日志和哈希；both缺项不写完成，alpha不强求MP4。
- [ ] 报告写入授权目的地，未读取无关会话/密钥、未自动修改系统或开启后台任务。
- [ ] 决策仅按证据列出、不凑数量；artifact交付未声称安装。
